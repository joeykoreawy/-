## 두 계정 브라우저 검증

각 계정은 분리된 브라우저 컨텍스트에서 웹 회원가입 양식을 통해 생성했습니다. 비로그인 확인용 별도 모바일 컨텍스트도 사용했습니다.

1. 태초만 활성화, 나머지 서버 3개는 준비 중으로 비활성화
2. 의뢰인 A와 기사 B 회원가입 및 각자의 비공개 연락처 저장
3. A 의뢰 등록 → B 및 비로그인 브라우저에서 같은 글 조회, 매칭 전 연락처 미노출
4. B 가격 제안 → A에게 표시, 비로그인 사용자에게 제안 상세 미노출
5. A 기사 선택 → 매칭 확정, A/B에게만 서로의 연락처 표시
6. 비로그인 사용자의 의뢰 수정 진입 차단
7. B 작업 시작 → A 완료 확인
8. 기사 B가 별도의 역할 전환 없이 의뢰 등록 화면도 사용 가능
9. 로그아웃 후 사이트 비밀번호로 재로그인
10. 실제 서버로 동시에 보낸 선택 요청 2개 중 하나만 성공, 중복 요청은 HTTP 409
11. 데스크톱/모바일 화면의 가로 넘침 없음, 브라우저 스크립트 오류 없음

실제 서버의 **별도 SQLite 파일**을 사용했고 HTTP 요청을 통해 저장·조회했습니다. 브라우저 저장소에 의존하지 않습니다. 합성 테스트 계정·연락처와 생성된 데이터는 `.local/e2e/`에만 있으며 실제 서비스 DB와 배포 ZIP에는 포함하지 않습니다.

## 서버 권한 검증

28개 테스트에서 익명 쓰기 차단, 타인의 의뢰 수정·삭제·선택 차단, 본인 의뢰 제안 차단, 타 의뢰의 제안 선택 차단, 중복 선택 차단, 다른 기사의 연락처/제안 비공개, 상태 전환 권한, 의뢰 수정 후 제안 재확인, 잘못된 서버/금액 거부, 수정 불가 필드 변조 무시, 제안 철회 권한, 취소·숨김 후 연락처 비공개, 신고 처리의 운영자 전용 권한, 신고 사본 보존, 연락처 삭제, 탈퇴 익명화, HTML 이스케이프, CSRF, GET 변경 요청 차단, 일반/관리자 로그인 시도 제한 등을 확인했습니다.

## 남은 공개 배포 검증

외부 호스팅 계정과 공개 URL이 아직 없습니다. PythonAnywhere 가입·WSGI 설정·실제 도메인의 HTTPS·호스팅 재시작 후 데이터 유지·외부 주소에서의 두 계정 흐름은 **미실행**입니다. 사용자 계정 설정 후 DEPLOYMENT.md의 절차를 따라 이어가야 합니다. 가짜 공개 URL이나 공개 배포 성공을 주장하지 않습니다.

Codex 개발환경용 `install_script`와 `start_skill`은 설정 초안에 저장했습니다. 이 저장은 외부 사이트 배포나 환경 게시를 실행하지 않습니다.
